## 2. Warm throughput: steady state

- **Java**: one JVM converts the same document `loop_warmup` times untimed, then `loop` times timed (`Convert --warmup W --loop N`). ms/doc and CPU ms/doc cover the timed loop only (CPU = process CPU time, JIT and GC threads included); *first* is the first conversion in the JVM (class loading + interpreter, no JVM startup); peak RSS is the whole process.
- **Rust in-process**: `wkhtmltopdf-inproc` calls `wkhtmltopdf_app::run` the same way (same warmup/loop counts, fresh stdin and output buffers per iteration).
- **Rust CLI loop**: `loop` sequential processes; ms/doc = elapsed / N, CPU ms/doc = (user+sys) / N, RSS = largest single process. The CLI has no daemon, so this is its steady state.
- Counts: `full warmup=3 runs=10 time_runs=3 loop_warmup=20 loop=30 heap_warmup=5 heap_loop=10`.
- On a shared host, *min* is the least disturbed figure (interference only adds time); compare medians only on an idle machine.

## 4. Output sanity

Page 1 of each engine's cold output at 60 dpi, side by side (left: wkhtmltopdf-rs, right: OpenHTMLtoPDF). Page counts differ by design: wkhtmltopdf lays out on a 96 dpi viewport and shrinks it to the printable width (smart shrinking), OpenHTMLtoPDF prints CSS sizes at their nominal size, so the same 11pt text takes more room. *Words* (in the cold table) is the `pdftotext` word count, a check that both outputs carry the whole text. `small.html` sets no font: the port's default face is DejaVu Sans (as QtWebKit's), OpenHTMLtoPDF's default family is serif, mapped here to DejaVu Serif. On `large`, OpenHTMLtoPDF does not repeat the `<thead>` on each page (it needs its proprietary `-fs-table-paginate: paginate`), hence 6 fewer words per continuation page.

## Caveats

- Wall-clock numbers depend on host load; this run's load average at start is in the Environment table. CPU time and peak RSS are far less sensitive. Rerun on an idle machine for wall-clock claims: `bench/java/run.sh --no-build`.
- The JVM uses several threads (JIT compiler, GC): its CPU time can exceed its wall time, and on a loaded host it competes for cores the single-threaded Rust conversion does not need.
- Layouts are not identical (see section 4), so per-document cost is not per-page cost: OpenHTMLtoPDF emits more pages for the same input.
- `-Xshare:auto` is already the JVM default; the tuned variant differs from the default by `-XX:TieredStopAtLevel=1` (C1 only). The AppCDS variant adds an archive of the classes one conversion loads, built into the image (`/opt/bench/app.jsa`).
- PDFBox logs font-fallback warnings while initialising its standard 14 fonts; stderr is discarded and the font cache (`~/.pdfbox.cache`) is prebuilt in the image, as it would be on a long-running server after its first start.
